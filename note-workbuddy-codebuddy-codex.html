✨ WorkBuddy + CodeBuddy + Codex 无缝接入

把任务编排、脚本执行、模型推理串成一条自动链路，
跨组件流转不再需要人工切窗口。

亮晶晶 工程自动化 WorkBuddy · CodeBuddy · Codex 2026-06-19
一句话结论：让 WorkBuddy 管编排、CodeBuddy 管执行、Codex 管推理，三者通过统一 JSON 上下文 + 环境变量密钥 + 标准中转脚本自动流转。适合批量数据处理、代码生成、文档解析等需要"流程 + 脚本 + 大模型"连续出活的工程场景。

🧩 各组件分工

组件 职责
WorkBuddy 任务编排、流程调度、参数传递、状态管理，作为整个链路的入口与控制器
CodeBuddy 执行自定义 Python / Shell 脚本、文件读写、API 请求、数据预处理、结果回传
Codex 代码生成、代码解析、文本推理、结构化输出，承接自然语言转代码、逻辑推演能力

流转链路：WorkBuddy 发起任务 → 传递上下文参数 → CodeBuddy 运行对接脚本 → 调用 Codex 接口 → 结果回写给 CodeBuddy → 回传 WorkBuddy 完成流程闭环。

📋 前置准备清单

  1. 开通 WorkBuddy 项目空间，获取项目访问密钥。
  2. CodeBuddy 环境确认：支持网络请求、Python 标准库，可安装 pip 依赖（按需）。
  3. Codex API Key、请求域名、接口版本（model 名称确认）。
  4. 统一上下文协议：JSON 格式传递入参、出参，保证三方数据兼容。

🔧 步骤 1：WorkBuddy 流程画布配置

  1. 新建工作流，添加【自定义节点】，节点类型选择「调用外部脚本 / CodeBuddy」。
  2. 定义输入变量：prompt、task_id、output_schema、user_params（统一使用 JSON 结构）。
  3. 开启参数透传：所有输入变量原样转发给 CodeBuddy，不做格式篡改。
  4. 配置回调地址：接收 CodeBuddy 执行完成后的返回 JSON，用于分支判断。
  5. 设置超时时间：建议 120s，适配 Codex 长文本推理场景。

🔧 步骤 2：CodeBuddy 接入中转脚本（Python 核心）

关键点：脚本职责仅做中转、参数校验、异常捕获，业务推理交给 Codex，保证三层职责解耦。 
"""
workbuddy_codex_bridge.py
作用：接收 WorkBuddy 入参 → 请求 Codex 接口 → 标准化返回结果给 WorkBuddy
"""
import os
import json
import requests

# ========= 配置区（从环境变量读取，禁止硬编码密钥）=========
CODEX_API_KEY = os.getenv("CODEX_API_KEY")
CODEX_ENDPOINT = os.getenv("CODEX_ENDPOINT")
MODEL_NAME = "codex"

def call_codex(prompt: str, schema: dict):
    headers = {
        "Authorization": f"Bearer {CODEX_API_KEY}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": MODEL_NAME,
        "prompt": prompt,
        "response_format": {"type": "json_object", "schema": schema},
        "temperature": 0.2
    }
    resp = requests.post(
        f"{CODEX_ENDPOINT}/v1/completions",
        headers=headers,
        json=payload,
        timeout=90
    )
    resp.raise_for_status()
    return resp.json()

def main():
    # 接收 WorkBuddy 传入的 JSON 参数
    input_raw = os.getenv("WORKBUDDY_INPUT")
    input_data = json.loads(input_raw)
    prompt = input_data.get("prompt", "")
    output_schema = input_data.get("output_schema", {})

    try:
        codex_result = call_codex(prompt, output_schema)
        return_data = {
            "success": True,
            "data": codex_result,
            "msg": "ok"
        }
    except Exception as e:
        return_data = {
            "success": False,
            "data": None,
            "msg": str(e)
        }
    # 标准输出 JSON，回传给 WorkBuddy
    print(json.dumps(return_data, ensure_ascii=False))

if __name__ == "__main__":
    main()

🔧 步骤 3：CodeBuddy 环境部署与权限配置

  1. 上传 bridge 脚本至 CodeBuddy 工作目录。
  2. 环境变量注入：CODEX_API_KEY、CODEX_ENDPOINT、WORKBUDDY_INPUT（由 WorkBuddy 运行时注入）。
  3. 网络白名单：CodeBuddy 出口 IP 加入 Codex 服务访问白名单。
  4. 依赖安装：pip install requests。
  5. 测试运行：手动构造 WORKBUDDY_INPUT 环境变量，验证脚本输出合法 JSON。

🔧 步骤 4：链路闭环与分支处理（WorkBuddy）

  1. CodeBuddy 执行完毕，JSON 结果回传 WorkBuddy。
  2. 增加判断分支：success = true / success = false。
  3. 成功分支：解析 data 字段，继续下游业务节点（文件生成、通知、入库）。
  4. 失败分支：捕获 msg 错误信息，支持重试（可配置重试次数、间隔），超过阈值触发告警。

⚠️ 无缝接入核心避坑清单

重点 1：密钥管理
所有 API Key 不写死脚本，全部通过环境变量注入，防止泄露。
重点 2：数据格式契约
全链路统一 JSON，禁止自由文本返回，否则 WorkBuddy 无法解析分支条件。
重点 3：超时与异常隔离
CodeBuddy 增加 try / catch，Codex 请求设置 timeout，防止单个节点阻塞整个工作流。
重点 4：职责边界
  • WorkBuddy：只管流程、调度、分支、存储上下文
  • CodeBuddy：脚本执行、网络转发、文件 IO、数据清洗
  • Codex：模型推理、代码生成、语义解析
重点 5：日志留存
CodeBuddy 打印完整出入参日志，WorkBuddy 保存节点执行记录，方便排障。

🖥 扩展：Shell 版本中转脚本（兼容无 Python 环境）

如果 CodeBuddy 所在环境没有 Python，可用 curl 直接中转：

#!/bin/bash
# workbuddy_codex_bridge.sh
INPUT_DATA=$WORKBUDDY_INPUT
CODEX_KEY=$CODEX_API_KEY
CODEX_URL=$CODEX_ENDPOINT

curl -s -X POST "$CODEX_URL/v1/completions" \
  -H "Authorization: Bearer $CODEX_KEY" \
  -H "Content-Type: application/json" \
  -d "$INPUT_DATA"

✅ 测试验证流程

  1. 单元测试：CodeBuddy 单独运行脚本，确认可正常调用 Codex 并返回 JSON。
  2. 联调测试：WorkBuddy 启动完整流程，观测参数透传、返回解析、分支流转。
  3. 异常测试：故意填写错误 Codex 密钥，验证失败分支、重试、告警是否生效。
  4. 压力测试：并发多条任务，观测各组件超时、限流情况。

🔍 常见问题排查

现象 根因 解决方案
WorkBuddy 拿到返回无法解析 脚本输出额外 print 日志，污染 JSON 仅最终结果 print json，中间日志写入文件，不输出 stdout
Codex 接口超时 prompt 过长、网络链路慢、timeout 设置过小 调大 timeout，拆分长任务，WorkBuddy 开启异步回调模式
密钥鉴权失败 环境变量注入失败、存在换行空格 在 CodeBuddy 脚本打印环境变量调试，去除首尾空白字符

🎯 落地总结

这套无缝接入方案实现了三层能力解耦：业务编排交给 WorkBuddy，脚本执行与中转交给 CodeBuddy，大模型推理交给 Codex。标准化 JSON 上下文 + 环境变量密钥管理 + 统一中转脚本，实现跨组件无人工介入自动流转，适合自动化数据处理、批量代码生成、文档解析类工程场景。
