✨ 用 WorkBuddy 管住"多框架任务"

国内用户一点经验：做建网站这类拆成好几个框架的事，
别靠翻聊天记录，用「1 个总框架会话 + N 个子会话」。

亮晶晶 效率方法 WorkBuddy 2026-08-03
一句话结论：多框架任务（比如建网站：框架A首页、框架B周报、框架C工具箱……），做完一个框架后，很容易忘了别的框架长啥样。我的办法——一个会话存整体框架，每个框架各开一个子会话；忘了对接哪个，点开总会话一目了然，不用往前翻半天。

📌 两个经验

经验 1

把总会话保留成一份文档

在总会话里让 AI 把整体框架整理成一份文档，你始终能看到全貌，进展到哪一步一目了然。

经验 2

新开对话做后续框架

框架A做完，新开一个子会话做框架B；不知道该做哪个时，点开总会话看一眼就清楚。

🔧 经验 1：保留文档，始终看全貌

做法：在总框架会话里，直接让 WorkBuddy 把已确定的框架整理成一份清单或文档（可用 .md / .html），保存下来。

  • 框架A / B / C / D 各自要做什么，一条条列清
  • 每做完一个，回来把"已完成"打勾或标注
  • 下次打开文档，全貌和进度都在，不靠记忆

为什么有效：多轮对话后，上下文越来越长，往前翻记录既慢又容易漏。一份文档把"整体"固定下来，脑子不用同时记好几件事。

🔧 经验 2：开新对话，单点突破

做法：完成框架A的大量互动后，新开一个对话专门做框架B，把"框架B的具体要求"带进去开工。

  • 每个子会话只聊一件事，上下文干净、不易跑偏
  • 卡住或忘了该做哪个 → 点开总会话（或那份文档）看一眼
  • 不确定下一步时，总会话就是你的"导航地图"

为什么有效：一个会话塞太多框架，AI 也容易前后混淆；拆开之后，每个会话目标清晰，产出更准。

⚠️ 一个前提：总框架会话和子会话，要在同一个空间（通俗讲就是同一个目录）。只有这样，它们才连得起来——你点开总会话能找到子会话，子会话也能回到总框架。不在同一空间，这两招就失效了。

✅ 适用场景

  • 建网站 / 做产品：首页、周报、工具箱、资源页……逐个落地
  • 写系列文档 / 课程：模块A、模块B 分别打磨
  • 任何"先定框架、再分块完成"的多步骤任务
